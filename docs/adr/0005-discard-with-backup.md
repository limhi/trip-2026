# 0005 編輯器可以把資料檔還原到上次發布，且一定先備份

日期：2026-10-26｜狀態：已決定，已實作（2026-10-26）

## 背景

存檔只寫進工作目錄，還沒 commit。使用者存了檔之後不要了，原本要自己在終端機用 `git restore`，而且 `git restore` 無法復原。Q13 當時決定「不做 undo，靠 git」；這裡補的是「整批退回上次發布」，不是編輯器內的逐步 undo。

## 決定

- 編輯器右上角「還原」選單有兩個動作：
  - 「放棄未存檔的修改」：重新載入磁碟內容並清掉伺服器記憶體裡的路線草稿，不改任何檔案。
  - 「還原到上次發布…」：把資料檔退回目前分支的 `HEAD`。
- 還原的範圍是發布清單內的 7 個資料檔，成套還原（工作目錄與暫存區一起）；不提供單檔或細粒度還原，因為資料檔彼此要同步，單檔還原會讓 `check.js` 失敗。其他檔案（`verify.md` 等）不碰。
- 一定先把 `git diff HEAD` 存成 patch 備份到 `.git/editor-backups/`（保留最近 20 份）；備份寫不進去就不還原。還原後用 `git apply --check` 確認備份能套回來。放在 `.git/` 內，不需要 `.gitignore`，也不會被誤 commit。
- 確認視窗列出會被丟掉的內容與「無法在編輯器內復原」的警告；沒有異動時選單項目是灰的。
- 任何分支都允許：還原只把資料檔退回已 commit 的版本，沒有 push 等外部動作。
- 會丟東西的端點（`/api/discard`、`/api/routes/reset`）要求自訂標頭 `X-Requested-With: trip-editor`，擋掉其他網頁用表單或 no-cors 請求觸發。

## 後果

- 好處：不用開終端機就能放棄不要的修改；備份讓這個動作有退路。
- 代價：備份用 `git apply` 套回，沒有「從備份復原」的介面；備份留在本機 `.git/` 內，換電腦或重新 clone 就沒有了。
- 已知缺口：發布（`POST /api/publish`）與存檔（`PUT /api/data`）還沒有同一層標頭保護（見 `docs/DESIGN.md` 14.8）。
