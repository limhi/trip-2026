# 0004 路線與交通時間由編輯器預先計算並快取

日期：2026-10-26｜狀態：已決定（尚未實作）

## 背景

公開頁面的地圖只是把標記用灰色虛線直線連起來，沒有真實道路、距離與時間。每段交通時間是手寫文字。使用者希望規劃期間就自動算出路線與時間。

## 決定

- 只有編輯器（本機）呼叫路線服務（OSRM 公開 demo）。結果存 `data/routes.json`，並產生 `data/routes.js`（距離與時間）和 `data/routes-geo.js`（路線座標，展開地圖才載入），一起 commit。
- 公開頁面只讀快取，不呼叫任何 API，不需要金鑰。離線（例如山區沒訊號）也能看。
- 快取存服務回傳的原始時間；顯示時間 = 原始 × 路況係數。係數在資料裡（全域預設 1.25，每天可覆寫），因為 OSRM 沒有路況預測。
- 快取 key 是起終點座標（各取 5 位小數），座標一改就自動算新的一筆；服務介面只有 `tools/routing/provider.js` 一個檔，要換 Google Routes 只改它。
- 失敗時退回直線並警告，不擋發布。
- 只開車。不做自動排程；與手寫時間不一致時只警告。
- 為此放寬「`js/` 除資料載入外不重構」：允許改 `js/map.js`、`js/blocks.js`、`js/model.js`。

## 後果

- 好處：公開頁面維持純靜態；服務掛掉或要換都不影響已發布的頁面。
- 代價：路線資料要 commit（`routes-geo.js` 會讓 repo 變大；已拆成展開地圖才載入）；沒有路況預測，準確度靠係數人工調整。
- OSRM 公開 demo 有使用限制，必須逐一請求、間隔至少 1 秒、帶識別專案的 `User-Agent`；用量遠低於上限，但不要改成批次大量查詢。
- 公開頁面不能改成即時呼叫服務：那會需要金鑰與額度，也失去離線能力。

## 考慮過的其他做法

- Google Routes API：有指定出發時間的路況預測，但要金鑰與計費；等 OSRM 的準確度不夠再換。
- 公開頁面即時呼叫：金鑰外洩、額度與離線問題。
- 全自動排程（由出發時間推算每項 `time`）：資料模型要重做，且現有時間有許多人為考量（場次、營業時段）。
