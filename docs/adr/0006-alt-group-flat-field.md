# 0006 擇一組用平的 `alt` 欄位，不用巢狀項目

日期：2026-10-30｜狀態：已決定，尚未實作

## 背景

使用者想把同一時段的兩個景點（Day 4 池上的大坡池與伯朗大道）做成「二選一」：當天只去其中一個，共用一個時間框，兩邊都要有前後車程的查詢時間與排定不足檢查。

## 決定

- `days[].items` 維持平的陣列。相鄰的 `spot` 填同一個 `alt`（字串）就是一個擇一組；共用時間寫在組內第一項的 `time`，其他成員不寫。
- 擇一組每個成員各自與前後站連成路段；地圖編號用同號加字母（3a、3b）。
- 驗證：成員只能是 `spot`、同一個 `alt` 必須相鄰、一組至少 2 項、只有第一項可寫 `time`。
- 編輯器用按鈕「併成擇一／移出擇一組」改 `alt` 欄位。

## 後果

- 好處：`getMapPoints`、`getLegs`、編輯器的列表與排序邏輯只需擴充，不必處理巢狀；既有資料不用搬移。
- 代價：「同一組」是靠相鄰與同名推導出來的，要靠驗證守住；擇一組只能放在同一天、連續位置。
- 之後若要擇一午餐（`meal`），放寬驗證即可，不必改資料格式。

## 考慮過的其他做法

- 新增 `choice` 項目、選項放 `options: [...]`：結構明確，但 `getMapPoints`、`getLegs`、編輯器與驗證都要改成處理巢狀。
- 沿用 `backup:true`：備案不連線、不算路段，無法做各自的車程與排定不足檢查。
